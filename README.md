# Agent 工作規則

本專案保存供新建與既有專案使用的 [Agent 工作規則](AGENTS.md)與[開發偏好](開發偏好.md)。本頁是專案導覽，也提供常用工作指令的快速說明；完整條件與流程以 AGENTS.md 為準。

## 如何導入

在目標專案開啟對話，貼上以下指令；使用本機來源時，將網址換成規則資料夾路徑。

```text
請先閱讀 https://github.com/howiedagg/rule 的 AGENTS.md 與開發偏好，再依導入流程套用到目前專案。
```

本儲存庫是規則來源，保留根目錄的 AGENTS.md 與開發偏好供讀取；下述文件結構適用於導入的目標專案。

## 理解

先閱讀開發偏好與既有專案長期要求，再依指定對象核對相關文件、實作及必要驗證，說明用途、現況、目標與差異、處理方向、影響和未確認事項。

對象可以是功能、流程、計畫、交接或待辦等，不限固定口令；一般提出需求或分析問題也採相同流程，只查相關範圍。回報後等待，不修改檔案或自動恢復開發。

## 分析專案

全面盤點專案內容，不限既有名稱、格式或位置；先閱讀開發偏好與既有專案長期要求，再查證主要功能、重要關係及文件與實作是否符合適用規範。回報問題、文件落差、未確認事項與整理建議後等待，不修改檔案。

## 導入

包含上述全面分析，並直接將指定規則套用到專案、整理成一套符合規則的必要文件，不須先下另一道分析指令；已有分析結果可沿用有效證據，補查變動部分。

- 目標專案以根目錄 `README.md` 作唯一專案導覽，`AGENTS.md` 同放根目錄；開發偏好、專案長期要求、docs、計畫、交接與代辦集中於 `【專案規則】/`。正式主題文件放在 docs 的主分類資料夾內，各類可按責任與關聯擴充多份 Markdown 及子資料夾，有內容才建立；完整分類依 AGENTS.md 第 1.2 節。
- 授權範圍包含必要文件的新增、整合、分類調整、重寫，以及完成替代與核對後的舊文件清理；修改或刪除前須有可恢復的內容基準。搬移時維護導覽與相對連結，不為位置調整重寫正確內容。
- 導入不自動修改產品程式、執行待辦或替原有任務驗收、收尾。
- 單純提供規則來源供閱讀、討論或修改規則本身，不會觸發導入或全面搬移；全新專案須先確認用途、首批範圍、限制與驗收方式。

## 整理長期要求

將已確認、持續適用的專案要求，依主題整理到「專案長期要求」，連結相關主題文件並維護導覽入口。區分要求與實作狀態，不把猜測或單次需求自行提升為長期要求。

明確要求才保存，不須等同步，也不代表授權產品實作；一般同步、暫緩不自動觸發。導入時可承接既有明確要求，依 AGENTS.md 處理。

## 同步

核對目前成果與有效證據，依各部分狀態更新正式文件，保存未完成工作的接續資料，並處理符合條件部分的收尾。

- 已確認成果與必要限制進入正式文件；未完成工作的需求、決策、差異、驗證及下一步保存在交接，保留原始任務基準。
- 實作、必要驗證與 review 完成，且有可觀察效果者已經使用者驗收、無未解相依問題，才可收尾；未完成部分繼續保存。
- 同步不代表所有工作都已完成，也不順便處理無關待辦。要求「暫緩」時，會先同步，再將指定任務轉存待辦。

## 使用提醒與確認方式

只有訊息為 `load` 時，會輕量載入規則、專案與工作狀態後等待；「等等」「先停一下」只停止，不自動同步或轉存。Commit 預設由使用者操作，不自動提交。

「開始做」「照這個改」「實作」才授權指定修改；「可以」「了解」不代表授權修改。直接要求建立或修改文件，即授權該次文件工作。
