# Agent 工作規則

本專案保存供新建與既有專案使用的 Agent 工作規則與開發偏好。本頁是專案導覽，也提供常用工作指令的快速說明。

## 理解

先了解指定對象的用途、現況、目標與差異，再核對相關文件、實作及必要驗證，說明處理方向、影響和未確認事項。

計畫、交接或待辦


## 導入

將指定規則實際套用到專案，盤點既有文件與專案實作，查證主要功能和重要關係，再整理成一套符合規則的必要文件。

- 授權範圍包含必要文件的新增、整合、分類調整、重寫，以及完成替代與核對後的舊文件清理；修改或刪除前須有可恢復的內容基準。
- 導入不自動修改產品程式、執行待辦或替原有任務驗收、收尾。
- 單純提供規則來源供閱讀或討論，不會觸發導入；全新專案須先確認用途、首批範圍、限制與驗收方式。

## 同步

核對目前成果與有效證據，依各部分狀態更新正式文件，保存未完成工作的接續資料，並處理符合條件部分的收尾。

- 已確認成果與必要限制進入正式文件；未完成工作的需求、決策、差異、驗證及下一步保存在交接，保留原始任務基準。
- 實作、必要驗證與 review 完成，且有可觀察效果者已經使用者驗收、無未解相依問題，才可收尾；未完成部分繼續保存。
- 同步不代表所有工作都已完成，也不順便處理無關待辦。要求「暫緩」時，會先同步，再將指定任務轉存待辦。


## 使用提醒與確認方式

只有訊息為 `load` 時，會輕量載入規則、專案與工作狀態後等待；「等等」「先停一下」只停止，不自動同步或轉存。Commit 預設由使用者操作，不自動提交。

「開始做」「照這個改」「實作」才授權指定修改；「可以」「了解」不代表授權修改。直接要求建立或修改文件，即授權該次文件工作。
